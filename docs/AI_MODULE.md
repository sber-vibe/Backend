# Контракт модуля AI-анализа документов (текущий прототип)

## Вход и маршрутизация

`POST /api/v1/ai/analyze`: `multipart/form-data`, поле `file` (PDF, DOCX, UTF-8 TXT, PNG, JPG, JPEG), до 10 MiB.

- PDFBox 3 читает текстовые страницы PDF и готовит PNG с полностью сканированных страниц (до двух).
- Apache POI читает текст и таблицы DOCX (не распознаёт изображения внутри DOCX).
- TXT читается как UTF-8; PNG/JPEG декодируются локально и передаются мультимодальной модели.
- Qwen3-VL получает извлечённый текст и/или изображения через локальный Ollama `/api/generate` со строгой JSON Schema.
- Java проверяет структуру и некоторые поля. Значения, которые отсутствуют в документе, возвращаются как `null`.

**Тип документа не извлекается из имени файла**: расширение выбирает лишь декодер. Классы `APPLICATION` и `UNKNOWN` – временные; схема официальных восьми классов пока отсутствует.

## Выход HTTP 200

```json
{
  "document_type": "APPLICATION",
  "fields": {
    "organization": "ООО Пример",
    "inn": "7707083893",
    "kpp": "773601001",
    "bank_inn": null,
    "bank_kpp": null,
    "document_date": "12.05.2020",
    "requested_amount": "1 250 000,50 руб.",
    "purpose": "Приобретение оборудования"
  },
  "uncertain_fields": [],
  "warnings": [],
  "needs_review": false
}
```

- `fields.*` – **строка или `null`**, строковые денежные суммы не нормализуются в API, проверяются через `BigDecimal` отдельно;
- `document_date` – исходная строка (форматы `ДД.ММ.ГГГГ` и `ГГГГ-ММ-ДД` проходят проверку календаря);
- `uncertain_fields` – список ключей, неуверенно распознанных моделью;
- `warnings` – список проверяемых проблем и сомнений, сгенерированный Java;
- `needs_review` – есть ли предупреждения, **не флаг одобрения**.

`unknown` всегда помечается предупреждением об ограниченности текущего классификатора. Отсутствие предупреждений не равно установлению достоверности документа. Сама модель может спутать должностное лицо с организацией или нормативное основание субсидии с целью расходования.

## Ошибки и безопасность

| Код | Условие |
| --- | --- |
| 413 | Слишком большой файл при загрузке |
| 422 | Некорректный/неподдерживаемый файл, нет подходящего содержимого, превышены лимиты документа |
| 503 | Ollama недоступна либо GPU занят |
| 504 | Время ожидания модели истекло |
| 502 | Некорректный ответ Ollama или ошибка связи |

Уровень доступа: **пока открытый диагностический endpoint**. Для реальных документов необходимы авторизация, ограничение запросов и безопасное хранение. Не передавать реальные пароли, клиентские сведения и документы, пока эти меры не реализованы.

## Границы интеграции с основной системой

Пока AI-результат не сохраняется в БД, не связан с идентификатором заявки, а основной `ApplicationService` проверяет лишь комплектность по типам, указанным клиентом. Для интеграции требуется согласовать тип документа, набор полей, статусы анализа и бизнес-правила **после выдачи официальной спецификации**. Сервер должен выполнять детерминированную проверку сумм/условий самостоятельно и учитывать решения специалиста.

## Настройки

`OLLAMA_URL` – адрес Ollama (по умолчанию `http://127.0.0.1:11434`), `OLLAMA_MODEL` – модель (по умолчанию `qwen3-vl:4b-instruct`). GPU-семафор: один запрос на процесс, соединение 5 секунд, чтение ответа 180 секунд.
