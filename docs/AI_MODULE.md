# AI-модуль: запуск, контракт и интеграция

Документ описывает исходники ветки `feat/ai-document-analysis`, передаваемые для дальнейшей разработки 10.10.2026. Это промежуточное состояние: качество распознавания и совместимость с актуальным `main` требуют проверки перед объединением.

## Быстрый старт

1. Используйте JDK 26 и Gradle Wrapper из репозитория, как описано в README.
2. Установите Ollama. Выполните `ollama pull qwen3-vl:4b-instruct`.
3. Убедитесь, что `curl.exe http://127.0.0.1:11434/api/tags` возвращает список моделей.
4. Задайте `OLLAMA_URL`, `OLLAMA_MODEL`, `AI_API_KEY` в окружении процесса Backend.
5. Запустите `.\gradlew.bat bootRun` либо конфигурацию **Backend Main** в IDEA.
6. Проверьте `/actuator/health`, затем отправьте синтетический документ в `/api/v1/ai/analyze`.

`/actuator/health` проверяет Backend; наличие рабочего AI подтверждается отдельным запросом на анализ. При запуске через IDEA переменные нужно задавать в Run Configuration, а не только в терминале.

```powershell
$env:OLLAMA_URL = "http://127.0.0.1:11434"
$env:OLLAMA_MODEL = "qwen3-vl:4b-instruct"
$env:AI_API_KEY = [guid]::NewGuid().ToString("N")
.\gradlew.bat bootRun
```

В другом терминале:

```powershell
$key = Read-Host "AI_API_KEY запущенного Backend"
$file = "C:\Documents\application.pdf"
curl.exe --max-time 1800 -X POST "http://localhost:8080/api/v1/ai/analyze" `
    -H "X-Api-Key: $key" `
    -F "file=@$file"
```

Для включённой JWT-защиты в актуальном Backend добавьте `-H "Authorization: Bearer $token"`, где `$token` содержит действительный JWT с ролью `specialist` или `admin`.

## Вход

`POST /api/v1/ai/analyze`, `multipart/form-data`, одно поле `file`. Параметр `type` не нужен: тип определяется по содержимому.

Форматы: PDF, DOCX, UTF-8 TXT, PNG, JPG, JPEG. Размер файла: до 10 MiB. XLSX и отдельный маршрут предпросмотра не входят в этот модуль.

Расширение выбирает декодер, а не тип документа. Парсер проверяет содержимое; переименование произвольного файла в `.pdf` не делает его допустимым PDF.

## Порядок обработки

1. `AiAnalysisService` занимает общий слот GPU. Повторный одновременный вызов `analyze()` получает `503`; очереди в этом методе нет.
2. `IsolatedDocumentContentReader` запускает дочерний Java-процесс с `DocumentParserWorker`. Тот извлекает текст и изображения через `DocumentContentReader`.
3. `AiChunkAnalyzer` классифицирует документ по первому текстовому фрагменту, до маркера второй страницы, если он есть.
4. Известный тип определяет набор полей. Извлечение выполняется по последовательным фрагментам до 4000 символов, с предпочтением разрыва на переводе строки.
5. При объединении сохраняется первое непустое значение. Различающиеся непустые значения отмечаются в `uncertain_fields`; сравнение строк точное, без нормализации.
6. Если в `APPLICATION` отсутствует `requested_amount`, выполняется дополнительное извлечение суммы из контекста и доступных изображений.
7. `AiResultPostprocessor` проверяет JSON и реквизиты, формирует окончательный ответ.

Для сканов изображения передаются классификатору и первому фрагменту. Изображения бюджетных страниц PDF с текстовым слоем используются в дополнительном извлечении суммы и не передаются на первичную классификацию.

Бюджетная страница определяется по совместному наличию в тексте подстрок «запрашиваем», «софинансирован», «итого». При отсутствии сканированных страниц отрисовываются последние найденные бюджетные страницы, до двух. Это эвристика, поэтому распознавание каждой возможной таблицы не гарантируется.

## Типы и поля

Набор `fields` зависит от типа. Ключи из других типов в ответ не добавляются.

| Тип AI | Назначение | Поля |
|---|---|---|
| `APPLICATION` | Заявление | `organization`, `inn`, `ogrn`, `kpp`, `document_date`, `requested_amount`, `signatory`, `purpose` |
| `PERSONAL_DATA_CONSENT` | Согласие на обработку персональных данных | `full_name`, `passport_details`, `document_date` |
| `CONFORMITY_CERTIFICATE` | Сертификат соответствия | `certificate_number`, `certification_body`, `issue_date`, `valid_until` |
| `PROJECT_PRESENTATION` | Презентация проекта | `project_name`, `project_description` |
| `COST_JUSTIFICATION` | Обоснование расходов | `total_expenses`, `own_funds`, `expense_items` |
| `BANK_STATEMENT` | Банковская выписка | `organization`, `inn`, `account_number`, `account_balance`, `document_date` |
| `REAL_ESTATE_DOCUMENT` | Документ на недвижимость | `cadastral_number`, `area`, `property_purpose`, `address`, `rights_holder` |
| `GUARANTEE_LETTER` | Гарантийное письмо | `organization`, `inn`, `guarantee_amount`, `document_date`, `signatory` |
| `UNKNOWN` | Тип не определён | Пустой объект `fields` |

Обязательные реквизиты в постобработке:

| Тип | Обязательные поля |
|---|---|
| `APPLICATION` | `organization`, `inn`, `requested_amount`, `document_date` |
| `PERSONAL_DATA_CONSENT` | `full_name`, `document_date` |
| `CONFORMITY_CERTIFICATE` | `certificate_number`, `valid_until` |
| `PROJECT_PRESENTATION` | `project_name` |
| `COST_JUSTIFICATION` | `total_expenses`, `own_funds` |
| `BANK_STATEMENT` | `organization`, `account_balance`, `document_date` |
| `REAL_ESTATE_DOCUMENT` | `cadastral_number` |
| `GUARANTEE_LETTER` | `organization`, `guarantee_amount`, `document_date` |

Эти проверки относятся к реквизитам одного документа. Они не задают обязательный состав пакета заявки.

## Выход HTTP 200

```json
{
  "document_type": "APPLICATION",
  "fields": {
    "organization": "ООО Пример",
    "inn": "7707083893",
    "ogrn": null,
    "kpp": "773601001",
    "document_date": "01.10.2026",
    "requested_amount": "1 250 000,50 руб.",
    "signatory": null,
    "purpose": "Приобретение оборудования"
  },
  "uncertain_fields": [],
  "warnings": [],
  "needs_review": false
}
```

- `fields.*` содержит строки или `null`. Отсутствующее значение не подменяется нулём.
- Денежные суммы и даты в этом API сохраняют исходный строковый вид. Для вычислений используйте `DocumentFieldChecks.parseAmount()` и `parseDate()`.
- `uncertain_fields` перечисляет сомнения модели и конфликты значений между фрагментами.
- `warnings` содержит предупреждения Java: отсутствующие обязательные поля, ошибки формата или проверки, сомнения распознавания.
- `needs_review` равен `true`, когда список предупреждений непустой. Это не решение о выдаче субсидии и не числовая уверенность.
- Для `UNKNOWN` возвращаются `fields: {}`, предупреждение «Тип документа не определён» и `needs_review: true`.

Постобработка проверяет контрольные цифры ИНН, девять цифр КПП, календарные даты, будущие даты выдачи/подписания, истёкший `valid_until`, суммы и формат кадастрового номера. Все денежные поля, кроме `account_balance`, должны быть положительными. Текущий код поэтому предупреждает и о нулевом `own_funds`; применимость этого правила нужно согласовать с условиями программы.

ОГРН, номер счёта и паспортные данные извлекаются, но специализированной проверки этих реквизитов в текущей постобработке нет. Предупреждение о скором истечении срока и сравнение сумм между документами также не выполняются здесь.

## Вызов из Java

Используйте Spring bean `AiAnalysisService` через внедрение зависимости:

```java
private final AiAnalysisService aiAnalysis;

public MyService(AiAnalysisService aiAnalysis) {
    this.aiAnalysis = aiAnalysis;
}

public String analyzeDocument(byte[] bytes, String filename)
        throws java.io.IOException {
    return aiAnalysis.analyze(bytes, filename);
}
```

Возвращается окончательный JSON, а не текст модели. Не вызывайте напрямую package-private `AiChunkAnalyzer` из слоя заявок.

Внутренний Java-вызов не проходит через HTTP-фильтр `X-Api-Key`. Не выполняйте синхронный анализ в потоке HTTP-загрузки заявки: используйте фоновый обработчик и состояния обработки. При `503` «busy» следует повторить задачу позже; не записывайте успешный результат.

## Интеграция с актуальным Backend

Проверенный `main` от 10.10.2026 содержит интеграцию:

`ApplicationDocumentRecognizer.recognize()` вызывает `AiAnalysisService.recognizeDocument()`, тот вызывает `VisionAnalysisClient.analyzeDocumentContent()`. В локальной версии ветки из архива методов `recognizeDocument()` и `analyzeDocumentContent()` нет.

**При объединении нельзя просто заменить эти классы поверх main:** сохраните методы и общую синхронизацию доступа к GPU либо адаптируйте распознаватель заявок к новому конвейеру. Документ описывает требуемые изменения; адаптер в этой версии ещё не реализован.

| Контракт этой ветки | Контракт распознавателя заявок в main | Действие при интеграции |
|---|---|---|
| `fields` – объект с ключами | `fields` – массив с `name`, `value`, `confidence`, `source` | Преобразовать структуру |
| `PERSONAL_DATA_CONSENT` | `PD_CONSENT` | Сопоставить enum |
| `organization` | `company_name` | Сопоставить ключ |
| `document_date` | `date` | Сопоставить ключ |
| `account_balance` | `balance` | Сопоставить ключ |
| Строковые суммы / даты | Нормализованные числа / даты | Использовать согласованный нормализатор Backend |
| `uncertain_fields`, `warnings`, `needs_review` | Числовая уверенность типа и полей | Передать предупреждения; без оценки уверенности использовать `null` |
| Фрагмент источника не возвращается | `source` у поля | Использовать `null`; не выдумывать источник |

У нового классификатора нет отдельных классов `GIMS_DECLARATION`, `REGISTRATION_EXTRACT`, `COST_ESTIMATE`, `SUPPORTING_DOCUMENT`, существующих в `DocumentType` актуального Backend. Не удаляйте эти классы и их правила из основной системы ради слияния AI-правок; поддержку нужно согласовать отдельно.

`warnings` и `needs_review` не должны теряться при адаптации. Нельзя выводить `confidence=1` из отсутствия предупреждений. После переноса проверьте загрузку → фоновую обработку → сохранение полей → проверку → отображение результата, а также исправление и повторную обработку.

README текущей ветки сохраняет описание её старого API заявок. При слиянии оставьте актуальные разделы `main` об авторизации и заявках; перенесите новые инструкции по AI и исправьте описание фактически выбранного контракта.

## Лимиты и время обработки

| Ограничение | Текущее значение |
|---|---|
| Входной файл | 10 MiB |
| Страницы PDF | До 30 |
| Текст документа | До 64 000 символов, превышение отклоняется |
| Изображения PDF | До двух сканированных страниц; при их отсутствии – до двух найденных бюджетных страниц |
| Изображение | До 20 000 000 пикселей |
| Фрагмент текста | До 4000 символов |
| Защитный предел фрагментов | 40 |
| Heap дочернего парсера | `-Xmx384m` |
| Время дочернего парсера | 30 секунд |
| Соединение с Ollama | 5 секунд |
| Ожидание одного HTTP-запроса к модели | 180 секунд |
| Контекст модели | `num_ctx=8192` |
| Лимит ответа | 1536 токенов; повтор при `length` с 3072 |
| Одновременный анализ | Один на экземпляр `AiAnalysisService` |

Общий анализ состоит из классификации, запросов по фрагментам и иногда отдельного запроса суммы. Общего тайм-аута всего анализа в коде нет. Не рассчитывайте на завершение длинного документа за 180 секунд; согласуйте ожидание фонового задания и тайм-ауты прокси.

Сканированные PDF более чем с двумя нетекстовыми страницами отклоняются. Изображения внутри DOCX отдельно не распознаются. Дочерний процесс ограничивает ресурсы парсера, но не является полноценной песочницей ОС.

## Диагностика ошибок

| Код / симптом | Что проверить |
|---|---|
| `400` | Наличие непустого поля `file` и корректность multipart |
| `401` | Правильный `X-Api-Key`; в объединённом Backend также действительный JWT |
| `403` при JWT-защите | Роль пользователя |
| `413` | Размер файла / multipart |
| `422` | Допустимый формат, содержимое, число страниц и лимит текста |
| `502`, invalid result | JSON, `done_reason`, доступность выбранной модели; причина записывается в журнал Backend |
| `Generation limit exceeded` | Обе генерации завершились по лимиту токенов; изучить журнал и документ |
| `503`, unavailable | Ollama работает и доступна по `OLLAMA_URL`; модель загружена; парсер запускается |
| `503` до запуска анализа | `AI_API_KEY` отсутствует или короче 32 символов |
| `503`, busy | Другой анализ занимает слот; повторить позже |
| `504` | Тайм-аут парсера либо запроса к модели |

Если `/api/tags` доступен, но анализ не проходит, проверьте имя модели в `ollama list` и переменные именно запущенного процесса. Для Docker адрес `127.0.0.1` относится к контейнеру; настройте адрес Ollama на хосте или в отдельном сервисе.
