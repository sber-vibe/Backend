# Backend – проверка пакета документов на субсидию

Заготовка для кейса «Агентство инноваций» на хакатоне Сбера. Java, Spring Boot 4.1.1, Gradle, REST API.

## Запуск

Для сборки используйте JDK 26 (совместим с Gradle 9.6 из проекта). Укажите `JAVA_HOME` на ваш JDK.

### IntelliJ IDEA: запуск через Main

1. Клонируйте этот репозиторий и откройте его корневую папку (с `settings.gradle` и `build.gradle`) как Gradle-проект.
2. Выберите установленный JDK 26 для Project SDK и Gradle JVM. Дождитесь завершения синхронизации Gradle: IDEA загрузит зависимости Spring и создаст модуль `SberCase.main`.
3. Выберите общую конфигурацию **Backend Main** и нажмите Run или Debug. Также можно запускать `main()` в `src/main/java/org/example/Main.java` кнопкой рядом с методом.

Конфигурация хранится в `.run/Backend Main.run.xml` и входит в репозиторий; локальные пути к JDK в ней не используются. Docker и PowerShell-скрипты для этого запуска не нужны.

Если IDEA запускает Java без classpath, проверьте, что Gradle синхронизирован, а в конфигурации запуска выбран модуль `SberCase.main`. Если порт 8080 занят, остановите предыдущий экземпляр приложения либо задайте переменную окружения `PORT=8081` в конфигурации запуска.

### Терминал

Выполняйте команды из корня клонированного репозитория:

```powershell
.\gradlew.bat test bootJar
.\gradlew.bat bootRun
```

Linux/macOS: `sh ./gradlew test bootJar`, затем `sh ./gradlew bootRun`.
Сервис: http://localhost:8080. Health: `GET /actuator/health`.
Порт задаётся переменной окружения `PORT`. Собранный JAR: `build/libs/backend.jar`.

```sh
docker build -t subsidy-backend .
docker run --rm -p 8080:8080 subsidy-backend
```

При запуске AI-модуля в Docker необходимо отдельно настроить доступ контейнера к Ollama через `OLLAMA_URL`. Адрес `127.0.0.1` внутри контейнера не указывает на хостовый компьютер.

## API заявок

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/document-types` | Обязательные типы документов демо |
| POST | `/api/v1/applications` | Создать заявку |
| GET | `/api/v1/applications` | Список заявок |
| GET | `/api/v1/applications/{id}` | Заявка, документы и последний отчёт |
| POST | `/api/v1/applications/{id}/documents` | Multipart: поля `type` и `file` |
| GET | `/api/v1/applications/{id}/documents/{documentId}` | Скачать документ |
| DELETE | `/api/v1/applications/{id}/documents/{documentId}` | Удалить документ |
| POST | `/api/v1/applications/{id}/check` | Проверить комплектность |

Создание заявки:

```json
{
  "applicantName": "ООО Инновации",
  "inn": "6161000000",
  "projectName": "Новый продукт",
  "requestedAmount": 100000
}
```

Пример сценария (bash; в PowerShell вызывайте `curl.exe`):

```sh
curl -X POST http://localhost:8080/api/v1/applications \
  -H 'Content-Type: application/json' \
  -d '{"applicantName":"Demo","inn":"6161000000","projectName":"Innovation","requestedAmount":100000}'
curl -X POST http://localhost:8080/api/v1/applications/UUID/documents \
  -F 'type=APPLICATION' -F 'file=@application.pdf'
curl -X POST http://localhost:8080/api/v1/applications/UUID/check
```

Замените `UUID` на `id` созданной заявки. Типы: `APPLICATION`, `REGISTRATION_EXTRACT`,
`COST_ESTIMATE` (обязательные), `SUPPORTING_DOCUMENT` (дополнительный).

Ошибки возвращаются в формате Problem Details (`application/problem+json`).
В API заявок ИНН проверяется только по длине и цифрам, сумма должна быть положительной.
Файл: до 10 MiB; форматы по расширению: PDF, DOCX, TXT, PNG, JPG, JPEG.
При загрузке в заявку фактическое содержимое и MIME-тип не проверяются. Скачивание выполняется как двоичный attachment.
До 100 заявок, 20 документов на заявку и 50 MiB файлов суммарно для одного процесса.

## AI-модуль анализа документов

Модуль `org.example.subsidy.ai` использует Qwen3-VL через Ollama. Эта версия описывает текущие правки ветки `feat/ai-document-analysis`: восемь типов документов, извлечение реквизитов по фрагментам текста и отдельное извлечение суммы из бюджетной таблицы.

**Инструкция для разработчика:** [docs/AI_MODULE.md](docs/AI_MODULE.md). Там приведены полный контракт, поля каждого типа, вызов из Java, ограничения и рекомендации по переносу в актуальный Backend.

### Быстрый запуск для разработки (Windows / PowerShell)

1. Установите Ollama и загрузите модель:

```powershell
ollama pull qwen3-vl:4b-instruct
ollama list
curl.exe http://127.0.0.1:11434/api/tags
```

Ollama должна работать до начала распознавания. Если она не запущена приложением, выполните `ollama serve` в отдельном терминале.

2. В терминале Backend задайте настройки и запустите приложение:

```powershell
$env:OLLAMA_URL = "http://127.0.0.1:11434"
$env:OLLAMA_MODEL = "qwen3-vl:4b-instruct"
$env:AI_API_KEY = [guid]::NewGuid().ToString("N")

.\gradlew.bat bootRun
```

`AI_API_KEY` должен содержать минимум 32 символа. Генерация выше создаёт временный ключ для локальной сессии. Для повторного запуска используйте согласованный ключ; в Git его не сохраняйте. При запуске из IntelliJ IDEA задайте эти переменные в **Run Configuration → Environment variables**: переменные терминала не передаются уже запущенной IDEA.

3. В другом терминале проверьте Backend и отправьте документ:

```powershell
curl.exe http://localhost:8080/actuator/health
$key = Read-Host "Введите AI_API_KEY из конфигурации Backend"
$file = "C:\Documents\application.pdf"

curl.exe --max-time 1800 -X POST "http://localhost:8080/api/v1/ai/analyze" `
    -H "X-Api-Key: $key" `
    -F "file=@$file"
```

HTTP API синхронный: результат возвращается после обработки всего документа. `--max-time` задаёт только время ожидания curl. Если в объединённом Backend включён Keycloak, дополнительно требуется `Authorization: Bearer <JWT>` с подходящей ролью.

### Настройки

| Переменная | Назначение / значение по умолчанию |
|---|---|
| `OLLAMA_URL` | Адрес Ollama, `http://127.0.0.1:11434` |
| `OLLAMA_MODEL` | Мультимодальная модель, `qwen3-vl:4b-instruct` |
| `AI_API_KEY` | Ключ диагностического HTTP API, минимум 32 символа |
| `PORT` | Порт Backend, `8080` |

Если Ollama работает на другом компьютере, укажите его доступный адрес. Для Backend в Docker Desktop и Ollama на хосте используйте `http://host.docker.internal:11434`. Для Linux-контейнера добавьте соответствующее сопоставление хоста, например `--add-host=host.docker.internal:host-gateway`. Ollama должна слушать адрес, доступный контейнеру.

### Что изменилось

- Классификация отделена от извлечения полей; поддерживаются восемь типов и `UNKNOWN`.
- Текст обрабатывается последовательными фрагментами до 4000 символов вместо одного короткого запроса.
- PDF: до 30 страниц; извлечённый текст: до 64 000 символов.
- При незавершённой генерации `done_reason=length` выполняется повторный запрос с увеличенным лимитом ответа: 1536 → 3072 токена. Это не гарантирует завершение: повторное превышение приводит к `502`.
- Для заявления без распознанной суммы выполняется дополнительный запрос по контексту суммы и доступным изображениям. В PDF с текстовым слоем могут быть отрисованы до двух найденных бюджетных страниц.
- Конфликтующие значения из разных фрагментов помечаются в `uncertain_fields`; сохраняется первое непустое значение.
- Java проверяет обязательные реквизиты для распознанного типа, ИНН, КПП, даты, суммы и формат кадастрового номера.

### Совместимость с интеграцией заявок

В этой локальной версии доступен `AiAnalysisService.analyze(byte[], String)`, который возвращает JSON с объектом `fields`, строками или `null`, `warnings` и `needs_review`.

В проверенном `main` от 10.10.2026 интеграция Андрея использует другой путь: `ApplicationDocumentRecognizer` → `AiAnalysisService.recognizeDocument()` → `VisionAnalysisClient.analyzeDocumentContent()`. В текущей версии ветки двух последних методов нет. При объединении сохраните или адаптируйте этот путь и его контракт `fields[]`, числовую уверенность и фрагменты источника. Полная замена файлов из этой ветки поверх `main` удалит точки входа интеграции.

Также требуется сопоставление `PERSONAL_DATA_CONSENT` → `PD_CONSENT` и `organization` → `company_name`. Подробности: [раздел интеграции](docs/AI_MODULE.md#интеграция-с-актуальным-backend).

Проверка перед объединением:

```powershell
.\gradlew.bat test bootJar
```

Эта инструкция сверена с исходниками. Прогон тестов и проверка на реальной модели должны быть выполнены на машине разработчика: в среде подготовки документации загрузка Gradle была недоступна.

## Границы заготовки

Перечень документов демонстрационный, а не официальный регламент субсидии.
Проверка выявляет недостающие типы и дубликаты. Неполный пакет получает `INCOMPLETE`,
полный – `REVIEW_REQUIRED`. Решение об одобрении сервис не принимает.
После загрузки или удаления документа предыдущий отчёт сбрасывается.

Данные заявок и загруженные в них файлы хранятся в памяти и теряются при перезапуске.
Авторизация основного API заявок пока не реализована; отдельный AI API защищён ключом `X-Api-Key`.
Для демонстрации используйте синтетические документы.

AI-анализ и извлечение реквизитов реализованы как самостоятельный модуль, но не интегрированы с проверкой заявок. Проверка подписей, постоянное хранилище PostgreSQL/S3 и роли пользователей пока не реализованы.

Для дальнейшей работы необходимо уточнить официальный регламент, заменить хранилище, интегрировать AI-анализ с заявками и согласовать общую модель авторизации с фронтендом.

GitHub Actions запускает тесты и сборку на push/PR.
