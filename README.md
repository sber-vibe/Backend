# Backend – проверка пакета документов на субсидию

Заготовка для кейса «Агентство инноваций» на хакатоне Сбера. Java, Spring Boot 4.1.1, Gradle, REST API.

## Запуск

Для сборки используйте JDK 26 (совместим с Gradle 9.6 из проекта). Укажите `JAVA_HOME` на ваш JDK.

### IntelliJ IDEA: запуск через Main

1. Клонируйте этот репозиторий и откройте его корневую папку (с `settings.gradle` и `build.gradle`) как Gradle-проект.
2. Выберите установленный JDK 26 для Project SDK и Gradle JVM. Дождитесь завершения синхронизации Gradle: IDEA загрузит зависимости Spring и создаст модуль `SberCase.main`.
3. Выберите общую конфигурацию **Backend Main** и нажмите Run или Debug. Также можно запускать `main()` в `src/main/java/org/example/Main.java` кнопкой рядом с методом.

Конфигурация хранится в `.run/Backend Main.run.xml` и входит в репозиторий; локальные пути к JDK в ней не используются. Docker и PowerShell-скрипты для этого запуска не нужны.

Если IDEA запускает Java без classpath, проверьте, что Gradle синхронизирован, а в конфигурации запуска выбран модуль `SberCase.main`. Если порт 8080 занят, остановите предыдущий экземпляр приложения либо задайте переменную окружения `PORT=8081` в конфигурации запуска.

### Терминал

Выполняйте команды из корня клонированного репозитория:

```powershell
.\gradlew.bat test bootJar
.\gradlew.bat bootRun
```

Linux/macOS: `sh ./gradlew test bootJar`, затем `sh ./gradlew bootRun`.
Сервис: http://localhost:8080. Health: `GET /actuator/health`.
Порт задаётся переменной окружения `PORT`. Собранный JAR: `build/libs/backend.jar`.

```sh
docker build -t subsidy-backend .
docker run --rm -p 8080:8080 subsidy-backend
```

При запуске AI-модуля в Docker необходимо отдельно настроить доступ контейнера к Ollama через `OLLAMA_URL`. Адрес `127.0.0.1` внутри контейнера не указывает на хостовый компьютер.

## Авторизация (Keycloak)

Если задан JWKS, `/api/**` принимает только JWT от Keycloak (`Authorization: Bearer …`) с realm-ролью `specialist` или `admin`:

| Переменная | Пример |
|---|---|
| `SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_JWK_SET_URI` | `http://keycloak:8080/kc/realms/subsidy/protocol/openid-connect/certs` |
| `SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_ISSUER_URI` | `http://localhost/kc/realms/subsidy` — issuer из токена (публичный адрес) |
| `SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_AUDIENCES` | `subsidy-backend` |

Проверяются подпись, срок действия, issuer и audience. Без токена — `401`, без нужной роли — `403`, оба в формате Problem Details.
Проверка `exp`/`nbf` допускает расхождение часов до 30 секунд. Каждый действующий access token,
включая выпущенный через refresh token, проверяется независимо; серверная сессия и привязка к значению
токена отсутствуют. Продление frontend выполняет напрямую в Keycloak. При заданном JWKS необходимо
задать issuer; audience по умолчанию `subsidy-backend`. Ошибки `401`/`403` содержат русский `detail`.
`/actuator/health` и `/actuator/info` открыты. Без JWKS API закрыт с `503`; открытый локальный режим требует явного профиля `dev` (`SPRING_PROFILES_ACTIVE=dev`).
`/admin/**` требует `admin`, заявки, оригиналы, проверки и решения — `specialist`. Роль `admin` сама по себе доступа к заявкам не даёт. Справочники доступны обеим ролям. Очередь заявок общая для специалистов; отказы доступа записываются в журнал.

При настроенном Keycloak AI API также требует JWT с подходящей ролью и ключ `X-Api-Key`.

## API заявок

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/document-types` | Доступные типы документов |
| GET | `/api/v1/programs` | Демонстрационный каталог программ |
| POST | `/api/v1/applications` | Создать заявку |
| GET | `/api/v1/applications` | Список заявок |
| GET | `/api/v1/applications/{id}` | Заявка, документы и последний отчёт |
| POST | `/api/v1/applications/{id}/documents` | Multipart: `file`, необязательный `type`; фоновое распознавание |
| PATCH | `/api/v1/applications/{id}/documents/{documentId}` | Исправить поля или тип документа |
| POST | `/api/v1/applications/{id}/documents/{documentId}/reprocess` | Повторить обработку после `FAILED` |
| GET | `/api/v1/applications/{id}/journal` | Журнал обработки и ручных правок |
| GET | `/api/v1/applications/{id}/documents/{documentId}/preview` | Office-просмотр: сначала `202`, затем HTML |
| POST | `/api/v1/applications/{id}/decision` | Сохранить решение специалиста |
| GET | `/api/v1/applications/{id}/documents/{documentId}` | Скачать документ |
| DELETE | `/api/v1/applications/{id}/documents/{documentId}` | Удалить документ |
| POST | `/api/v1/applications/{id}/check` | Проверить комплектность |

Создание заявки:

```json
{
  "programCode": "INNOVATION"
}
```

Пример сценария (bash; в PowerShell вызывайте `curl.exe`):

```sh
curl -X POST http://localhost:8080/api/v1/applications \
  -H 'Content-Type: application/json' \
  -d '{}'
curl -X POST http://localhost:8080/api/v1/applications/UUID/documents \
  -F 'type=APPLICATION' -F 'file=@application.pdf'
curl -X POST http://localhost:8080/api/v1/applications/UUID/check
```

Замените `UUID` на `id` созданной заявки. Обязательные типы определяет выбранная программа; актуальный перечень возвращает `/api/v1/programs`. При настроенном Keycloak добавьте заголовок `Authorization: Bearer <access token>`.

Ошибки возвращаются в формате Problem Details (`application/problem+json`).
Ошибки API заявок содержат понятное описание на русском языке.
Файл: до 50 MiB; форматы по расширению: PDF, DOC, DOCX, XLS, XLSX, TXT, PNG, JPG, JPEG.
При загрузке в заявку фактическое содержимое и MIME-тип не проверяются. Скачивание выполняется как двоичный attachment.
До 100 заявок, 20 документов на заявку и 50 MiB файлов суммарно для одного процесса.

### Реквизиты и обработка

При создании принимается только необязательный `programCode`: `{}` и `{"programCode":null}` тоже возвращают `201`.
Организация, ИНН, проект и сумма первоначально равны `null`. Они извлекаются из первого загруженного заявления
(`APPLICATION`); источник, уверенность и история ручной правки доступны в `requisites`.
Удаление заявления или изменение его типа пересчитывает карточку.

Загрузка сразу возвращает `201` и `processingStatus: "UPLOADED"`. Последовательно работающая очередь
запускает классификацию и извлечение через Ollama; при занятой модели документ ждёт.
Перечитывайте заявку до `DONE` или `FAILED`. При ошибке `processingError` содержит причину на русском;
повторную обработку можно запустить через `/reprocess`. Для этого сценария `X-Api-Key` не требуется:
доступ регулируется общей авторизацией API заявок. Ollama и модель должны быть доступны серверу Backend.

Нераспознанные поля имеют `value: null` и `status: "NOT_RECOGNIZED"`; подстановка демонстрационных значений
не выполняется. Денежные значения возвращаются числами, даты — в формате `YYYY-MM-DD`.
Низкая уверенность распознавания даёт предупреждение в отчёте.

Пример ручной правки: `{"fields":[{"name":"requested_amount","value":900000}]}` или
`{"type":"GUARANTEE_LETTER"}`. `originalValue` сохраняет значение до первой правки;
`correctedBy` берётся из `preferred_username` проверенного JWT. Без Keycloak используется «Специалист».
Ручное изменение типа сохраняет предложение модели в `detectedType`. Правки записываются в журнал
и сбрасывают предыдущий отчёт. Ручные значения сохраняются при завершении фоновой обработки и повторном распознавании.

Проверка возвращает `PROCESSING`, пока документы обрабатываются. Арифметика и сверка сумм выполняются
только на распознанных числах: отсутствие значения даёт `WARNING`, а не успешную проверку.
Каждое замечание содержит `severity`, `documentId` и `field` для перехода к источнику.

### Программы, правила и решения (FE-01…FE-06)

Отчёт возвращает явные `PASSED`, `ATTENTION`, `ERRORS` или `PROCESSING`. Документ после проверки
имеет `outcome` из того же набора итогов (`PASSED`, `ATTENTION`, `ERRORS`); до проверки итог равен `null`.
Ошибка обработки или неизвестный тип не дают успешного результата. Любое изменение документов
сбрасывает отчёт и итоги файлов. Замечания содержат также `rule` — код правила.

Комплектность вычисляется по выбранной или распознанной программе. Неопределённая программа
даёт предупреждение. `REQUIRED` нужен всегда; `CONDITIONAL` содержит понятное человеку `condition` и код `conditionAttribute` из `/api/v1/application-attributes` (`requiresCertification`, `usesWaterArea`).
Специалист задаёт атрибуты через `PATCH /api/v1/applications/{id}` с `{"attributes":{"requiresCertification":true}}`.
`true` требует документ, `false` исключает его из перечня, `null` или отсутствие дают `CONDITIONAL_UNKNOWN`. Изменение атрибутов сбрасывает отчёт. Дополнительные типы отмечаются `EXTRA`.

Администратор может читать/создавать/изменять программы через `/api/v1/admin/programs`
(`GET`, `POST`, `PUT /{code}`) и читать/изменять правила через `/api/v1/admin/rules`
(`GET`, `PUT /{code}`). В режиме Keycloak требуется роль `admin`.
Правила поддерживают включение, строгость и типы документов; параметры: уверенность (`threshold`),
допуск по суммам (`tolerance`), минимальная доля собственных средств (`minOwnFundsShare`, 0..1),
предупреждение о сроке действия (`daysBeforeExpiry`). Изменения применяются при следующей проверке.
При первой инициализации создаются INNOVATION, BEACH и MODERNIZATION с перечнями документов из кейса; минимальная доля собственных средств — 0.5. Проверка подписей остаётся ручной и по умолчанию даёт `ATTENTION`.
При `PUT` передавайте полученную `version`: устаревшая или отсутствующая версия возвращает `409`. `updatedBy` и `updatedAt` назначает сервер. `paramSchema` задаёт единицы, границы и обязательность параметров; проценты вводятся в интерфейсе как 0..100, но API принимает долю 0..1.
Изменения настроек и аудит записываются в БД одной транзакцией. Проверка использует снимок настроек на момент запуска; готовые отчёты не пересчитываются сами.
`/api/v1/admin/journal?limit=200&before=<ISO instant>&action=PROGRAM_UPDATED` объединяет события заявок и настройки администратора: новые первыми, `before` строго исключительный. Изменения содержат `before`, `after`, `version`, `objectType`, `objectId`.

Решение: `POST /applications/{id}/decision` с `{"decision":"RETURNED","comment":"Дослать документы"}`.
Возможны `ACCEPTED`, `RETURNED`, `REJECTED`; для возврата/отклонения комментарий обязателен.
Автор берётся из JWT. Решение хранится отдельно от автоматического отчёта и сохраняется при его сбросе.
Без готового отчёта или во время обработки решение возвращает `409`. Повторное решение сохраняет прежнее и новое значения в журнале.

Данные сохраняются в файловой БД H2: `STORAGE_JDBC_URL` по умолчанию `jdbc:h2:file:./data/subsidy`. Заявки, оригиналы, реквизиты, отчёты, решения, настройки и журналы переживают перезапуск. В Compose каталог `/app/data` подключён к volume `backend-data`; не удаляйте volume при обновлении. Прерванная обработка после перезапуска получает `FAILED` и допускает повторный запуск. БД рассчитана на один экземпляр backend.

DOC/DOCX/XLS/XLSX доступны в статическом HTML-просмотре: текст Word и таблицы Excel,
со встроенными стилями и экранированием содержимого; изображения и исходная вёрстка Office не воспроизводятся.
Первый запрос `/preview` возвращает `202` с `Retry-After: 3`; готовый — `200 text/html`, повреждённый —
`422` с русским описанием. Конвертация работает в отдельном процессе с ограничениями памяти/времени,
не выполняет макросы и формулы. Оригинал остаётся доступен для скачивания. Доступ требует той же роли,
что и чтение документа.

Фоновое задание ограничено 240 секундами (`DOCUMENT_PROCESSING_TIMEOUT_SECONDS`, 1..600).
По истечении времени документ получает `FAILED`; очередь продолжает обработку следующих файлов.
Запрос повторной обработки записывается в журнал как `DOCUMENT_REPROCESS_REQUESTED`.

## AI-модуль анализа документов

Отдельный модуль `org.example.subsidy.ai` анализирует документы с использованием локальной мультимодальной модели Qwen3-VL через Ollama.

Возможности:

- Извлечение текста из PDF с текстовым слоем, DOCX и TXT (UTF-8).
- Анализ сканированных PDF, PNG и JPEG.
- Классификация по содержимому документа.
- Извлечение названия организации, ИНН и КПП заявителя, банковских реквизитов, даты, суммы и назначения субсидии.
- Проверка формата и контрольных цифр ИНН, формата КПП, календарных дат и денежных сумм.
- Формирование предупреждений и признака необходимости ручной проверки.

Обработка нейросетью выполняется через настраиваемый сервер Ollama. По умолчанию используется локальный адрес; документы не отправляются в облачные AI API.

### Подготовка и настройка

Установите Ollama и загрузите модель:

```powershell
ollama pull qwen3-vl:4b-instruct
```

Переменные окружения Backend:

| Переменная | Назначение |
|---|---|
| `AI_API_KEY` | Обязательный ключ доступа к AI API, минимум 32 символа |
| `OLLAMA_URL` | Адрес сервера Ollama, по умолчанию `http://127.0.0.1:11434` |
| `OLLAMA_MODEL` | Имя модели, по умолчанию `qwen3-vl:4b-instruct` |

Если `AI_API_KEY` отсутствует или не соответствует минимальной длине, AI API возвращает `503 Service Unavailable`. Ключ задаётся в переменных окружения процесса или Run Configuration IntelliJ IDEA и не должен храниться в репозитории.

### HTTP API

**`POST /api/v1/ai/analyze`**

- Тип запроса: `multipart/form-data`.
- Поле файла: `file`.
- Поддерживаемые форматы: PDF, DOCX, TXT, PNG, JPG, JPEG.
- Максимальный размер входного файла: 50 MiB.
- Авторизация: заголовок `X-Api-Key`.

Пример запроса из PowerShell:

```powershell
$key = Read-Host "AI API key"
$file = "C:\Documents\application.pdf"

curl.exe -X POST "http://localhost:8080/api/v1/ai/analyze" `
    -H "X-Api-Key: $key" `
    -F "file=@$file"
```

Пример структуры ответа:

```json
{
  "document_type": "APPLICATION",
  "fields": {
    "organization": "ООО Пример",
    "inn": "7707083893",
    "kpp": "773601001",
    "bank_inn": null,
    "bank_kpp": null,
    "document_date": "12.05.2020",
    "requested_amount": "1250000",
    "purpose": "Приобретение оборудования"
  },
  "uncertain_fields": [],
  "warnings": [],
  "needs_review": false
}
```

`document_type` содержит распознанный тип документа. `fields` содержит извлечённые значения; отсутствующие значения представлены `null`. Массив `uncertain_fields` перечисляет сомнительно распознанные реквизиты, `warnings` содержит результаты проверок, а `needs_review` сигнализирует о необходимости ручной проверки.

Отсутствие предупреждений не является подтверждением подлинности документа, корректности всех сведений или права заявителя на субсидию.

При проблемах с AI или парсером возможны ответы `401` (неверный ключ), `422` (файл не обработан), `502` (ошибка обработки), `503` (сервис недоступен или занят), `504` (тайм-аут).

### Устойчивость и ограничения

- Разбор файлов выполняется в отдельном Java-процессе с ограничением Java heap и времени выполнения.
- Предусмотрены ограничения размеров изображений, PDF-страниц, элементов DOCX и распакованных данных.
- Одновременно выполняется не более одного анализа в рамках экземпляра Backend.
- Для запросов к Ollama установлены тайм-ауты.
- Инструкции внутри документов считаются недоверенными данными, но защита от prompt injection не гарантирует абсолютную устойчивость.
- Дочерний процесс парсера не является полноценной песочницей операционной системы.
- При доступе через недоверенную сеть необходимы HTTPS или защищённый туннель; API-ключ сам по себе не шифрует трафик.

Текущие функциональные ограничения:

- Отдельный `/ai/analyze` использует классификатор из `feat/ai-document-analysis` и объект `fields`.
  Фоновая обработка заявок сохраняет полный набор типов API документов и контракт `fields[]` с источниками и уверенностью.
- PDF: не более 30 страниц; для анализа изображений используются не более двух сканированных страниц.
- Извлечённый текст ограничен 64 000 символами; запросы к модели выполняются по фрагментам до 4000 символов.
  Тип первого фрагмента фиксируется для последующих. Противоречивые реквизиты в заявке получают `null`.
- При `done_reason=length` запрос повторяется с увеличенным лимитом генерации (1536 → 3072 токена).
- Изображения, встроенные в DOCX, не анализируются отдельно.
- Результат фонового AI-анализа сохраняется в памяти заявки и участвует в проверке.

Для проверки:

```powershell
.\gradlew.bat clean test
```

## Границы заготовки

Перечень документов демонстрационный, а не официальный регламент субсидии.
Проверка выявляет недостающие типы, дубликаты и ошибки значений. Недостающий обязательный документ
даёт `ERRORS`, ручная проверка — `ATTENTION`. Решение об одобрении принимает специалист отдельно.
После загрузки, удаления или ручной правки документа предыдущий отчёт сбрасывается.
Обнаруженные арифметические ошибки дают `ERRORS`, если правило настроено со строгостью `ERROR`.

Данные заявок и загруженные в них файлы хранятся в памяти и теряются при перезапуске.
Авторизация `/api/**` — через Keycloak при заданном JWKS (см. выше); AI API дополнительно защищён ключом `X-Api-Key`.
Для демонстрации используйте синтетические документы.

AI-анализ и извлечение реквизитов интегрированы с заявками. Проверка подписей и постоянное хранилище PostgreSQL/S3 пока не реализованы. Доступ к API при включённом Keycloak ограничен ролями `specialist` и `admin`.

Для дальнейшей работы необходимо уточнить официальный регламент и заменить хранилище.

GitHub Actions запускает тесты и сборку на push/PR.
